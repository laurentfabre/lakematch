# LM-014 comparison UI — bounded development plan

Date: 2026-09-22. LF-B remains **8/8 experiments**. No cap extension is approved.

Hypothesis: business users can distinguish actual source values, normalized
agreements, conflicts and exclusions in the existing APX golden-record demo.
The synthetic fixture supplies memberships; comparison must not imply a trained
score, discovered candidates or permission to merge.

Add explicit pair origin to the portable comparator: retrieved candidates still
require method provenance; directly selected comparisons carry no retrieval
methods. Version the changed evidence algorithm and check probability replay
against this origin. Retain deterministic precedence and review/exclude routing.

At build time, compare each of the six fixture companies' two source snapshots
in each of the two publications. Export a typed display projection alongside
the existing golden records, with original comparison/ruleset digests. The app
reads only its packaged JSON; keep Python 3.12 worker imports outside the Python
3.11 app. Label missing scores explicitly and show no merge action.

Bounds: exactly twelve exported comparisons from the existing tiny integration
fixture, seven fields each, maximum 1 MiB packaged JSON. No pilot corpus,
fitting, threshold search, confirmation generation, cloud resource, database
integration experiment or acceptance-quality measurement. Ordinary app unit
tests may use disposable local SQLite stores; no existing store is changed.

Verify pair-origin validation, evidence replay, source/version correspondence,
identifier conflicts and deletion/history through focused portable/app tests.
Use existing 120-second test limits, APX type checks, the pinned production
build (240 seconds per build step), and the existing bounded loopback browser
preview. Check desktop/mobile layout, keyboard disclosure, publication switching,
error recovery, and that preview reads never fetch/write the review queue.
Stop owned preview processes after evidence capture. Keep historical reports,
frozen Phase A checksums and dependency pins unchanged.

Update the goal and Phase B checkpoint with observed development results. Leave
empirical calibration, registry promotion, live comparison adapters, authenticated
domain grants, full acceptance and Phase B closure open. Commit locally through
managed hooks; publication still awaits the repository-visibility decision.
